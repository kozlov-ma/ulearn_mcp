# ulearn-mcp

MCP для преподавателя [ulearn.me](https://ulearn.me): материалы курса, решения студентов, очередь ревью, комментарии, оценки за решения, баллы за модули и активность. Курс по умолчанию — `nand2tetris`.

## Подключение

Нужны Rust 1.88+, Cargo и Git. В своём терминале выполните:

```sh
cargo install --git https://github.com/kozlov-ma/ulearn_mcp.git --locked
ulearn-mcp bootstrap-session
ulearn-mcp config --session
```

Войдите в ulearn в браузере и откройте ведомость. В DevTools → Network выберите запрос к `ulearn.me`, скопируйте значение заголовка `Cookie` и вставьте в скрытый ввод `bootstrap-session`. Передавать cookie в чат не нужно. Команда проверит аккаунт и сохранит сессию; отдельный API-токен вводить не требуется. Подробная инструкция: `ulearn-mcp bootstrap-session --help`.

`config --session` выведет JSON: замените запись `ulearn` из `mcpServers` в настройках MCP-клиента, сохранив остальные подключения, и перезапустите подключение. В JSON находятся абсолютные пути и адреса сервисов, секретов в нём нет. После настройки аккаунт можно проверить командой `ulearn-mcp --check`.

Если раньше использовался токен, замените старую запись целиком: явный `ULEARN_TOKEN_FILE` или `ULEARN_TOKEN` сохраняет режим токена даже при наличии файла сессии по умолчанию. Удалите эти переменные из новой записи и из окружения, где запускаете проверку. Одновременно явно задавать сессию и токен нельзя.

Если команда не найдена, добавьте `~/.cargo/bin` в `PATH`. Пока репозиторий приватный, нужен выданный владельцем доступ и авторизация GitHub; при настроенном SSH можно установить так:

```sh
cargo install --git ssh://git@github.com/kozlov-ma/ulearn_mcp.git --locked --config net.git-fetch-with-cli=true
```

Правила работы с ревью передаются агенту при подключении MCP, в том числе после `cargo install`. Отдельно устанавливать skill не требуется; его текст доступен в [skills/ulearn-review/SKILL.md](skills/ulearn-review/SKILL.md).

## Что попросить у агента

**Сначала черновик, затем отдельное явное одобрение пользователя.** Агент должен показать точные комментарии/ответы и предлагаемую оценку для конкретной попытки либо студента, модуля и категории, затем дождаться подтверждения перед публикацией. «Проверь», «сделай ревью» и «оцени» означают подготовить результат, а не записать его в ulearn.

- «Покажи темы курса и задания в теме “Память”».
- «Прочитай материалы темы и объясни, какие знания нужны для решения Clock».
- «Подготовь 10 вопросов для устной защиты домашки по памяти с ожидаемыми ответами».
- «Добавь пять коротких проверок понимания, которые можно задать прямо на занятии».
- «Покажи ожидающие ревью в моих группах, затем только по группе X и задаче PC».
- «Открой попытку №N студента X по задаче Clock вместе с условием и результатами проверок».
- «Сравни историю попыток этого студента: что исправлено, а какие проблемы остались?».
- «Прочитай прошлые замечания к решению и проверь, учёл ли их студент».
- «Подготовь черновик ревью этой попытки: привяжи каждое замечание к строкам и условию задачи».
- «Предложи оценку по этой рубрике и обоснуй каждое снижение; пока ничего не публикуй».
- «Для найденной ошибки придумай минимальный пример и объясни ожидаемое и фактическое поведение».
- «Сократи второй комментарий и сформулируй его понятнее, сохранив суть замечания».
- «Подготовь ответ на вопрос студента в существующей ветке ревью».
- После просмотра черновика: «Для попытки №N одобряю публикацию комментариев 1 и 3 и оценку 75%; комментарий 2 не публикуй».

## Возможности

| Задача | Инструменты |
| --- | --- |
| Курсы, темы, условия и содержимое уроков | `list_courses`, `get_course`, `get_slide` |
| Учётная запись, группы, студенты, очередь и история ревью | `get_account`, `list_groups`, `list_students`, `list_review_queue` |
| Исходники, проверки, предыдущие замечания, контекст точной попытки | `get_submissions`, `get_review_context` |
| Баллы студента по модулям и категориям | `get_module_scores` |
| Изменение одобренных дополнительных баллов за модуль/активность | `set_module_score` |
| Публикация одобренного комментария, ответа или оценки | `add_review_comment`, `reply_to_review`, `set_review_score` |

Доступ определяется правами аккаунта ulearn. Для другого курса укажите `course_id`. Очередь можно фильтровать по группам, студентам и задачам; решения читаются по точным идентификаторам попыток.

## Баллы за модули и активность

`get_module_scores` принимает `course_id`, `user_id`, необязательные `unit_id` и `group_id`. Он возвращает по каждому видимому модулю категории оценивания: баллы за задания, дополнительные баллы, их сумму и максимум. Категории определяются курсом: например, `activity` — активность, `homework` — сдача преподавателю. Общая взвешенная оценка курса не вычисляется.

`set_module_score` меняет дополнительные баллы выбранной категории: например, активность за модуль. Передаются точные `course_id`, `unit_id`, `user_id`, `scoring_group_id`, новое `score`, прежнее `expected_score` и необязательный `group_id`. Балл — целое число от нуля до максимума категории; явный `score: null` очищает оценку. Прежнее отсутствие оценки задаётся `expected_score: null` и отличается от нуля. Суммарный результат модуля напрямую не перезаписывается.

Перед записью MCP проверяет прежнее значение, доступность категории и максимум, после записи перечитывает баллы. Для изменения нужна настройка через `bootstrap-session`: проверки API и запись в ведомость используют один аккаунт и одну зафиксированную сессию. Комментарии и оценки отдельных решений по-прежнему доступны через инструменты ревью.

Примеры запросов: «Покажи баллы студента за модуль “Память” по категориям», «Сколько баллов за активность у студента по каждому модулю?», «Подготовь изменение активности за модуль с 1 до 3 баллов». Публикация или очистка выполняется после отдельного одобрения показанного изменения.

## Сессия и обновление токена

В основном режиме единственный сохранённый секрет — cookie сессии. MCP получает из неё JWT через `POST /account/token`, проверяет аккаунт и хранит JWT только в памяти. Перед API-запросом отсутствующий или истекающий токен получается заново. Обновление планируется с запасом до пяти минут; для короткоживущего JWT запас составляет половину срока, оставшегося при получении. Истёкший JWT тоже заменяется, пока сама сессия действительна. Срок JWT задаёт ulearn.

Принудительно проверить обмен сессии на новый JWT можно командой:

```sh
ulearn-mcp refresh-token
```

В режиме сессии `--days` недоступен. Эта команда получает токен только для своего процесса; запущенный MCP автоматически получает собственный токен. Саму cookie MCP не продлевает, ответы `Set-Cookie` не сохраняет. Когда сессия истечёт, снова войдите в браузере и выполните `ulearn-mcp bootstrap-session --replace`.

Замена файла сессии для того же аккаунта подхватывается при следующей операции. Смена аккаунта требует перезапуска MCP и повторного чтения проверяемых работ/баллов. На время каждой записи фиксируются сессия и полученный из неё JWT; изменение файла между проверкой и отправкой останавливает запись. После `401` текущий запрос не повторяется: кеш JWT сбрасывается, новый токен получает только следующая операция. После таймаута или неизвестного результата записи автоматических повторов также нет.

### Совместимость с отдельным токеном

Прежний режим остаётся доступен через `ulearn-mcp bootstrap [TOKEN_FILE] [--replace]`: пользователь копирует JWT со страницы [ulearn.me/token](https://ulearn.me/token), а команда проверяет и сохраняет его. Этот режим поддерживает чтение модульных баллов и операции ревью; запись дополнительных баллов требует сессии.

В режиме отдельного токена MCP продлевает ещё действующий JWT преподавателя через `POST /account/api-token` при остатке не более пяти минут. По умолчанию выдаётся токен на 30 дней; `ULEARN_TOKEN_REFRESH_DAYS` задаёт 1–365 дней, `ULEARN_AUTO_REFRESH_TOKEN=false` отключает это продление. Команда `ulearn-mcp refresh-token --days 30` требует файл токена. Файл заменяется атомарно и перечитывается перед запросами; при `ULEARN_TOKEN` обновление живёт только в памяти процесса. Уже истёкший отдельный токен восстанавливается вручную через `ulearn-mcp bootstrap --replace`.

## Устройство и обслуживание

Сервер написан на Rust с `rmcp`, работает через stdio и обращается к API ulearn. Инструменты записи могут менять данные, видимые студенту: согласие проверяет агент, сервер не видит переписку и технически не доказывает его наличие.

- Перед записью ревью сервер повторно проверяет исходники по SHA-256 и предыдущую оценку; для баллов модуля проверяет прежнее значение и ограничения категории. Это защита от устаревшего контекста, а не атомарная блокировка.
- Координаты комментариев: строки с нуля, колонки в UTF-16. Оценка — целый процент 0–100, не число баллов; её запись завершает оценивание попытки.
- При неизвестном результате записи агент сначала перечитывает попытку или баллы модуля и сверяет результат. Автоматических повторов нет.
- Очередь ограничена (по умолчанию 50 работ) и не гарантирует полноту. HTML возвращается как данные; видео и внешние архивы не скачиваются. Студенческий код не исполняется и не считается инструкциями агенту.

`bootstrap-session [SESSION_FILE] [--replace]` сохраняет cookie в `~/.config/ulearn-mcp/ulearn.cookie` либо `$XDG_CONFIG_HOME/ulearn-mcp/ulearn.cookie`. Можно указать другой абсолютный путь аргументом или через `ULEARN_SESSION_FILE`. На Unix файлы секретов доступны только владельцу (`0600`); символьные ссылки не принимаются. API-JWT режима сессии на диск не записывается.

Без явно заданных учётных данных для стандартной установки выбирается существующий файл сессии, затем прежний `ulearn.token`. Явные `ULEARN_TOKEN_FILE`/`ULEARN_TOKEN` выбирают прежний режим; их сочетание с явным `ULEARN_SESSION_FILE` отклоняется. Для другой установки нужны явно заданные `ULEARN_API_URL`, `ULEARN_WEB_URL` и путь сессии. Секрет из стандартного файла не передаётся автоматически на другой сервер.

`.env` автоматически не загружается. `config` выбирает настроенный режим, `config --session` явно формирует настройку сессии, в том числе до создания её файла. Обе команды не читают содержимое секретов и не обращаются к сети. Для обновления повторите команду установки и перезапустите MCP-клиент; файлы авторизации сохранятся. `cargo uninstall ulearn-mcp` удаляет программу и сохраняет эти файлы.

Подробности контрактов и ограничений: [API_CONTRACT.md](API_CONTRACT.md). Порядок анализа, согласования и публикации: [правила ревью](skills/ulearn-review/SKILL.md).

Для локальной разработки клонируйте репозиторий, выполните `cargo build --release --locked`; настройку сессии для этой сборки выдаёт `./target/release/ulearn-mcp config --session`. Проверки из каталога исходников:

```sh
cargo fmt --check
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
python3 scripts/smoke_mcp.py --binary target/release/ulearn-mcp
```

Тесты используют локальные подставные HTTP-серверы. Успешный обмен реальной cookie на JWT в ходе разработки не проверялся; реальные комментарии и оценки не публиковались.
