# ulearn-mcp

Локальный MCP-сервер на Rust для преподавателя [ulearn.me](https://ulearn.me). Передаёт агенту темы и задания курса, исходный код решений, результаты проверок и очередь ревью. Позволяет оставлять комментарии, отвечать в обсуждениях ревью и выставлять оценку.

Транспорт — **stdio**. Курс по умолчанию — `nand2tetris`; в инструментах можно указать другой `course_id`. Доступ определяется правами учётной записи ulearn.

## Сборка и первоначальная настройка

Нужен Rust 1.88 или новее с Cargo. Запустите в своём терминале:

```sh
cd ~/Projects/ulearn_mcp
cargo build --release --locked
./target/release/ulearn-mcp bootstrap
```

`bootstrap` объяснит, где взять токен: войдите в свой аккаунт на [ulearn.me/token](https://ulearn.me/token) и нажмите «Скопировать токен». Вставьте его в терминал — ввод скрыт. Пароль ulearn для этого не нужен, подходит и аккаунт с внешним входом.

Команда проверяет токен запросом `GET /account`, затем сохраняет его в `~/.config/ulearn-mcp/ulearn.token` (или `$XDG_CONFIG_HOME/ulearn-mcp/ulearn.token`). Новая папка имеет права `0700`, файл — `0600` на Unix. Секрет не выводится в консоль или MCP и не попадает в конфигурацию. Без успешной проверки файл не создаётся и не меняется.

MCP автоматически читает этот файл для стандартного API ulearn. При другом API автоматическая загрузка отключена: нужно явно задать `ULEARN_TOKEN_FILE` или `ULEARN_TOKEN`. Переменные окружения имеют приоритет над стандартным файлом.

Проверка и обновление токена:

```sh
./target/release/ulearn-mcp --check
./target/release/ulearn-mcp bootstrap --replace
```

Срок действия токена определяется ulearn; автоматического продления нет. Если он истёк, снова скопируйте токен со страницы и выполните `bootstrap --replace`. Существующий файл заменяется атомарно только после успешной проверки нового токена. Уже работающий MCP нужно перезапустить.

Для собственного пути используйте `bootstrap /absolute/path/ulearn.token`; команда также учитывает `ULEARN_TOKEN_FILE`. После сохранения она печатает конфигурацию подключения с путём к файлу, без самого токена. Показать инструкцию без ввода и сохранения: `bootstrap --help`.

Токен даёт доступ к аккаунту. Вводите его только в локальный терминал; не отправляйте в чат и не передавайте как аргумент MCP-инструмента. Без токена доступны публичные материалы курса.

Альтернатива для аккаунтов с паролем ulearn: `ulearn-mcp login /absolute/path/new.token` — скрытый ввод пароля и сохранение JWT в новый файл. Команда `login` не перезаписывает существующие файлы.

## Подключение к MCP-клиенту

Для клиентов, поддерживающих конфигурацию `mcpServers`, добавьте запись ниже. Используйте абсолютные пути и при необходимости замените имя пользователя. Клиент запускает процесс без аргументов и общается с ним через stdin/stdout.

```json
{
  "mcpServers": {
    "ulearn": {
      "command": "/Users/kozlovma/Projects/ulearn_mcp/target/release/ulearn-mcp",
      "env": {
        "ULEARN_TOKEN_FILE": "/Users/kozlovma/.config/ulearn-mcp/ulearn.token"
      }
    }
  }
}
```

| Переменная | Назначение |
| --- | --- |
| `ULEARN_TOKEN_FILE` | Явный путь к JWT; без него используется стандартный файл bootstrap. Обычный файл, без символьной ссылки; на Unix доступ только владельцу. |
| `ULEARN_TOKEN` | Альтернатива: JWT из окружения. Нельзя задавать одновременно с `ULEARN_TOKEN_FILE`. |
| `ULEARN_API_URL` | По умолчанию `https://api.ulearn.me`. Для другой установки нужен HTTPS; HTTP разрешён только для локальных тестов. Токен отправляется этому серверу. |

Файл `.env` автоматически не загружается. Секреты не должны попадать в репозиторий или конфигурацию с общим доступом.

## Инструменты

| Инструмент | Что возвращает или меняет |
| --- | --- |
| `get_account` | Текущая учётная запись и роли по курсам. |
| `list_courses` | Доступные курсы и их идентификаторы. |
| `get_course` | Темы (`units`), уроки и задачи (`slides`), максимальные баллы; необязательный `group_id`. |
| `get_slide` | Полное содержание урока/задачи: HTML, код, блоки упражнения и настройки. |
| `list_groups` | Группы курса; `offset`, `count` (1–100). |
| `list_students` | Студенты группы и их стабильные `user_id`. |
| `list_review_queue` | Ожидающие ревью, либо история при `history: true`; фильтры по группам, студентам и задачам. |
| `get_submissions` | Все возвращённые API попытки одного студента по одной задаче; с `submission_id` — строго указанная попытка. |
| `get_review_context` | Точная попытка, условие задания и сведения о теме одним вызовом. `submission_id` обязателен. |
| `add_review_comment` | Публикация комментария к выделенному фрагменту кода. |
| `reply_to_review` | Публикация ответа в существующей ветке ревью. |
| `set_review_score` | Выставление оценки за ревью в процентах и завершение оценивания этой попытки. |

Очередь по умолчанию показывает до 50 работ из ваших групп, начиная со старых. `students_filter`: `mygroups`, `all`, `groupids`, `studentids`; для последних двух нужны соответствующие `group_ids` или `student_ids`. Порядок задаётся `sort: "ascending"` или `"descending"`. `min_timestamp` применяется только к истории. Очередь не резервирует работу и не гарантирует получение всех решений: API не предоставляет для неё offset/cursor.

Содержание слайдов и решений возвращается структурированным JSON без потери полей. HTML не преобразуется в Markdown, видео и внешние архивы автоматически не скачиваются. Для остальных уроков темы используйте их ID из `get_course` и `get_slide`.

## Работа с ревью

Последовательность: `list_review_queue` → `get_review_context` → анализ → `add_review_comment` / `reply_to_review` → `set_review_score`.

Все операции записи требуют `target` с `course_id`, `slide_id`, `user_id`, `submission_id`, `expected_code_sha256` и `expected_percent`. Хеш берётся из поля `code_sha256` прочитанной попытки, предыдущая оценка — из `manualChecking.percent` (`null` означает отсутствие оценки). Перед записью сервер повторно читает попытку и сверяет исходный код и оценку. Если они изменились, нужно заново получить контекст. Проверка не является атомарной блокировкой от параллельного изменения другим преподавателем.

В `add_review_comment` строки и колонки нумеруются **с нуля**, колонки измеряются в **UTF-16**, как в редакторе ulearn. Например, диапазон `(0, 0)` — `(0, 5)` выделяет первые пять UTF-16 единиц первой строки. Текст комментария или ответа должен быть непустым и не длиннее 10 000 UTF-16 единиц.

`set_review_score` принимает целое `percent` от 0 до 100, **не количество баллов**. Интерфейс ulearn предлагает 0, 25, 50, 75 и 100%. Этот инструмент не переключает разрешение будущих ревью для студента.

Комментарии и оценки сразу видны студенту. Сервер не добавляет отдельного диалога подтверждения: политику разрешения записи задаёт MCP-клиент и ваши инструкции агенту. Исходники и комментарии студентов следует рассматривать как данные, а не инструкции; сервер не исполняет присланный код.

Записи автоматически не повторяются. При таймауте результат может быть неизвестен: сначала перечитайте попытку через `get_submissions`, проверьте комментарии/оценку и только после этого решайте, нужен ли повтор. Если запись принята, но последующее чтение не удалось, результат содержит `write_accepted: true` и `readback_error`; это не повод повторять публикацию. Для оценок `score_verified` отражает совпадение прочитанной оценки с запрошенной.

## Примеры запросов агенту

- «Покажи темы nand2tetris и задания в теме “Машинный язык”».
- «Покажи ожидающие ревью в моих группах. Для первой работы прочитай условие и точную попытку, подготовь замечания».
- «Сравни попытки этого студента по указанной задаче и объясни, что изменилось».
- «Опубликуй эти замечания к выбранной попытке и поставь 75% за ревью».

## Проверки и ограничения

```sh
cargo fmt --check
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
python3 scripts/smoke_mcp.py --binary target/release/ulearn-mcp
# Опционально: чтение публичного курса через настоящий MCP, без токена
python3 scripts/smoke_mcp.py --binary target/release/ulearn-mcp --live
```

Тесты используют локальный подставной HTTP-сервер и не публикуют комментарии или оценки в ulearn. Контракты сверены с текущей документацией и кодом интерфейса; запись в реальном преподавательском аккаунте при разработке не проверялась. Ответ API ограничен 16 MiB. Учтены ошибки авторизации, запрет перенаправлений с токеном и неопределённый результат записи. Подробности и источники — в [API_CONTRACT.md](API_CONTRACT.md).
